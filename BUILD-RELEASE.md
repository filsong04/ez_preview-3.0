# EZ Preview · Release Candidate Build Guide

This repository contains the **v1.0.0-rc.3** packaging candidate. The user-facing app runs offline after installation: Electron and FFmpeg are packaged with the app. A developer needs internet access to restore npm dependencies and download build tools.

## App icon

The user-supplied black-and-yellow EZ logo is used for macOS (`.icns`), Windows (`.ico`), and Linux/common (`.png`/`.svg`) icon assets. See `build/ICON-ASSETS-README.md` for the icon inventory. Run `npm run test:native` to check their signatures, dimensions, and package configuration along with app regression tests.

## Build outputs

- **macOS Catalina legacy (Intel x64):** DMG and ZIP built with Electron 32.3.3 and minimum system version 10.15.0. This runtime is end-of-support; keep this build for compatibility testing or explicitly limited legacy users, not as the recommended general-public build.
- **macOS 12+ Intel (x64):** DMG and ZIP built with Electron 44.9.0.
- **macOS 12+ Apple silicon (arm64):** DMG and ZIP built natively on an Apple-silicon runner with Electron 44.9.0.
- **Windows x64:** NSIS setup installer and portable EXE built with Electron 44.9.0.

## Recommended build path: GitHub Actions

For a guided push from your Mac, see [PUBLISH-RC3.md](PUBLISH-RC3.md). The helper initializes a new source repository only after confirmation and refuses to overwrite an existing `.git` folder.

1. Create a private GitHub repository for the release source and upload this directory's contents. Do not upload signing certificates or API keys into the repository.
2. Push the source to the repository's default branch.
3. In GitHub, open **Actions → Build EZ Preview release candidates → Run workflow**. You can also push a tag such as `v1.0.0-rc.3` to trigger the build.
4. A dependency job resolves one npm lockfile for the run. The platform jobs download that same lockfile, install dependencies, run regression tests, and build native installers. Each artifact includes the lockfile, SPDX SBOM, FFmpeg build/license reports, third-party notice draft, and SHA-256 checksum manifest.
5. Wait for all macOS and Windows jobs to pass. Download the platform artifacts from the completed workflow run.
6. Test each installer on a clean target computer, including opening a representative MXF clip, audio, LUT persistence, folder import, proxy cache, fullscreen, and both PNG export paths.

The workflow publishes build artifacts to the Actions run; it does **not** automatically publish a public GitHub Release or sell the app.

Before stable 1.0.0, review the lockfile generated by the CI build, commit a reviewed `package-lock.json` to source control, and make builds consume that committed lock. This RC3 workflow resolves a temporary shared lock because this authoring environment cannot reach npm's registry.

## Local build (modern OS)

Use Node.js 24 and npm on a recent macOS 12+ or Windows computer. Avoid building all operating systems from one host; the native FFmpeg binary and platform packaging must match the target OS/architecture.

```bash
npm install --no-audit --no-fund   # first checkout only; creates package-lock.json
npm run release:preflight
npm run test:native
```

Commit `package-lock.json`, then use `npm ci` for subsequent builds.

On a modern macOS computer (macOS 12+):

```bash
npm run dist:mac:intel   # Intel output when running on/building for x64
npm run dist:mac:arm64   # Apple-silicon output when running on/building for arm64
```

On Windows x64:

```powershell
npm run dist:win
```

Local builds are written to `release/`. The Catalina legacy profile is intentionally built by the CI workflow on an Intel macOS runner using Electron 32.3.3.

## Optional signing secrets for CI

Without signing credentials, the workflow can create **unsigned** test installers. Do not distribute unsigned packages as a polished public release.

macOS GitHub Actions repository secrets:

- `MACOS_CERTIFICATE_P12_BASE64`: base64-encoded Developer ID Application certificate `.p12`
- `MACOS_CERTIFICATE_PASSWORD`: certificate export password
- `APPLE_API_KEY_P8_BASE64`: base64-encoded App Store Connect API private key (`.p8`)
- `APPLE_API_KEY_ID`: API key ID
- `APPLE_API_ISSUER`: API issuer UUID

The workflow prepares the API key for macOS notarization when both the key and signing certificate are configured. Successful notarization of both the modern and Catalina compatibility profile must be confirmed from the build logs and on a clean Mac.

Windows repository secrets:

- `WINDOWS_CERTIFICATE_P12_BASE64`: base64-encoded code-signing certificate `.p12`
- `WINDOWS_CERTIFICATE_PASSWORD`: certificate export password

Never put a certificate, key, password, or `.env` file in source control.

## Required gates before a paid 1.0.0 public release

See `RELEASE-BLOCKERS.md`. In particular, settle FFmpeg/GPL redistribution compliance, copyright/EULA text, signed/notarized installation, reproducible lockfile, and clean-machine tests before calling an installer final.
